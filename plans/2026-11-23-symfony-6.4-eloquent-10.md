# DiBe: upgrade Symfony 5.4 → 6.4 (phase 1) and Eloquent → 10 (phase 2)

> **For agentic workers:** this plan is self-contained and meant to be executed after a context clear. At the start,
> copy it to `plans/2026-11-23-symfony-6.4-eloquent-10.md` (repo convention).
> Required skills: superpowers:executing-plans, superpowers:verification-before-completion; use
> superpowers:systematic-debugging when a check fails. Before each PR, have a fresh reviewer subagent review the diff.
> **Create pull requests only. Never merge PRs and never push to `main`.**
> All PHP/composer commands run inside the container: `docker exec dibe-dev-symfony-1 sh -c 'cd /app && …'`.

## Context

The backend runs Symfony 5.4 (end of life) with Eloquent 8 (`illuminate/*` 8.83) through `wouterj/eloquent-bundle` 2.5.0.
This upgrade is a **stepping stone to Symfony 7 / Laravel 11+**. So besides getting onto supported versions, each phase
has to finish with **no deprecations from our own code**.

The phases can't be fully separated. `illuminate/http`, `illuminate/console` and `illuminate/session` v8 require
`symfony/* ^5.4`, so Symfony 6.4 needs illuminate 9 or later. The installed bundle 2.5.0 accepts SF `^5.4||^6.0` and
illuminate `^8.68||^9||^10`. Bundle 2.6+ needs SF 6+ and illuminate 9+; 2.8.1 accepts illuminate 9–12 and SF 6–7.
Both targets resolve: I ran `composer update --dry-run` on a scratch copy.

**Decisions taken with the user**
- Phase 1 = Symfony 6.4 + illuminate **^9** (bundle stays 2.5). Phase 2 = illuminate **^10** + eloquent-bundle **^2.8**.
- Aim for zero deprecations from our own code (preparing for SF 7).
- `TestController` and `TestElasticsearchCommand` are **refactored and kept**, not deleted.
- PHP **8.3**: commit the pending `Dockerfile` change (`PHP_VERSION=8.2 → 8.3`) in phase 1.

**My calls (correct them if needed)**
- Drop the unused packages `kirschbaum-development/eloquent-power-joins` (no usages in `src/`),
  `symfony/proxy-manager-bridge`, `composer/package-versions-deprecated`, `symfony/security-bundle` (not in
  `bundles.php`; `security.yaml` is in `_disabled/`), and `doctrine/annotations` once routes are attributes.
- Delete the leftover Encore configs `config/packages/{prod,qas,test}/webpack_encore.yaml`.
- Apply Rector's PHP rules one by one (only the rule for `${var}` interpolation), not the whole `php83` level set,
  so the diff stays reviewable.
- Keep `ajcastro/eager-load-pivot-relations` at v0.2.2 unless it breaks: it has no illuminate constraint and
  overrides `Builder::eagerLoadRelation(array, $name, Closure)`, whose signature is unchanged in L9/L10.

## Phase 0: baseline (before touching anything)

There are no PHP tests (`tests/` holds only vitest files). Regressions are caught by **snapshots** taken before and
after each phase. Write `app/scripts/upgrade-snapshot.sh <outdir>` and commit it in phase 1, because it can be reused for
SF 7. It does three things:
1. `bin/console debug:router --format=json` → `routes.json` (route names, paths, defaults, requirements, priority).
2. Reindex a fixed sample (`app:elasticsearch:index charter 300`, `… tradition 300`). Then dump every doc of
   `${ELASTICSEARCH_INDEX_PREFIX}_{charter,tradition}_{en,fr}`: `_source`, sorted by id, `jq -S`, one file per index.
   Use curl via `docker exec dibe-dev-elasticsearch-1` with the ES credentials from env. **This is the main regression
   check for the Eloquent upgrades:** the documents come from models → resources.
3. Run curl against the running app (`http://localhost:8000` in the container) and record the status code and body
   (JSON, `jq -S`) for:
   - `/`, `/en/`, `/fr/about`, `/en/charters`, `/en/tradition`
   - `/en/charters/{id}` with `Accept: application/json`, and as HTML (status only)
   - `/en/charters/search?…`, `/paginate`, `/locate`, `/aggregation_suggest?field=…&value=…`, `/search_syntax`
   - `/en/tradition/search_api`, `/paginate`, `/tradition/paginate` (legacy), `/en/tradition/{type}/{id}`
   - `/health`, `/test/search_api`, `/test/dump`

Run it on `main` → `var/snapshots/before/` (gitignored location under `var/`).

## Phase 1: Symfony 6.4 + Eloquent 9 — branch `chore/symfony-6.4`, one PR

Do steps 1–3 while still on 5.4. The app keeps working, so each change can be verified on its own.
Commit after each step (`chore:` / `refactor:`).

1. **PHP 8.3**: commit the `Dockerfile` change. In `app/composer.json`: `"php": ">=8.3"` and
   `config.platform.php: "8.3"`.

2. **Remove `ContainerInterface` autowiring.** The alias was removed in SF 6 and it already shows in
   `var/cache/dev/App_KernelDevDebugContainerDeprecations.log`.
   - `src/Command/IndexElasticsearchCommand.php`: inject `CharterRepository`, `OriginalRepository`, `CopyRepository`,
     `CodexRepository`, `CharterIndexService` and `TraditionIndexService` through the constructor. Replace
     `$this->container->get($repository_name)` with a private `name => repository` map built in the constructor
     (same keys as today: `original_repository`, …).
   - `src/Command/TestElasticsearchCommand.php`: inject `CharterRepository`.
   - `src/Controller/TestController.php`: inject `CharterSearchService` / `CharterRepository` (constructor, as the other
     controllers do with `searchService`), and drop the `ContainerInterface` action arguments.
   - `src/Controller/TraditionController.php::getSingle()`: drop the unused `ContainerInterface $container` argument.
   - The aliases in `config/services.yaml` (`App\Repository\CharterRepository: '@charter_repository'`, …) already
     make these autowirable. Keep the named public services; the startup script and commands don't need more.
   - Verify: `bin/console app:elasticsearch:index charter 10`, `/test/*` routes, and the deprecation log no longer
     lists the alias.

3. **Rector on 5.4** (`rector/rector` 2.x is already a dev dependency; add `app/rector.php`):
   - `->withPaths([__DIR__.'/src'])`
   - `->withAttributesSets(symfony: true)`: turns the 24 `@Route` annotations into `#[Route]`. Check
     `priority: -10` on `charter_get_single` and `defaults: ['_locale' => 'en']` on `tradition_paginate_legacy`.
   - `->withRules([CommandPropertyToAttributeRector::class, VariableInStringInterpolationFixerRector::class])`:
     `$defaultName`/`$defaultDescription` → `#[AsCommand]`, and fixes the `${var}` deprecation.
   - Run `vendor/bin/rector process --dry-run`, review, then apply.
   - `config/routes/annotations.yaml`: `type: annotation` → `type: attribute`, and rename the file to `attributes.yaml`
     (also for the `kernel` resource).
   - Remove `doctrine/annotations`. Remove the packages listed under "My calls" with
     `composer remove … ` (power-joins, proxy-manager-bridge, package-versions-deprecated, security-bundle).
   - Verify: `debug:router --format=json` is identical to the baseline.

4. **Bump composer** (`app/composer.json`):
   - Every `symfony/*` `5.4.*` / `^5.4` / `^5.2` → `6.4.*`, `symfony/runtime` → `6.4.*`, `symfony/flex` → `^2`
   - `extra.symfony.require: "6.4.*"`. This is essential: without flex enforcing it, transitive components resolve to
     7.4, as the dry-run showed.
   - `illuminate/http: ^9.52`, plus an explicit `illuminate/database: ^9.52`
   - `symfony/maker-bundle: ^1.50` stays (it resolves to 1.67)
   - Then `composer update -W`. Expect monolog 2 → 3, psr/log 3, psr/container 2, doctrine/lexer 3. No project code
     uses them directly.

5. **Recipes**: `composer recipes` then `composer recipes:update <pkg>` for each outdated recipe
   (framework-bundle, routing, twig-bundle, monolog-bundle, web-profiler-bundle, debug-bundle, …). Review each diff.
   Keep our customisations: `parameters.yaml`, `translation.yaml` (`enabled_locales`), `eloquent.yaml`,
   `services.yaml` services, `prod/routing.yaml`. Expected SF 6.4 config changes:
   - `framework.yaml`: `http_method_override: false`, `handle_all_throwables: true`, `php_errors.log: true`
   - drop `session.storage_factory_id` if the recipe does
   - `validator.yaml`: `email_validation_mode: html5`
   - `routes/framework.yaml` for errors
   - delete `config/packages/{prod,qas,test}/webpack_encore.yaml`

6. **Rector SF sets**: `->withSets([SymfonySetList::SYMFONY_60, …_61, …_62, …_63, …_64])` and
   `->withSymfonyContainerXml(__DIR__.'/var/cache/dev/App_KernelDevDebugContainer.xml')`. Expected changes:
   `configure(): void` return types, `Command::SUCCESS`, `Request` API renames. Dry-run, review, apply.

7. **Eloquent 8 → 9 adjustments**. The code surface is small: models use relations, the
   `TraitCustomModelSchema` overrides of `belongsTo/belongsToMany/hasMany/hasOne/hasManyThrough`, and
   `TraitLocalizedAttributes`. The resources extend `Illuminate\Http\Resources\Json\JsonResource`.
   - Fix the existing "might add `mixed` return type" deprecations: add `: mixed` to `getAttribute()` and
     `mutateAttribute()` in `src/Model/TraitLocalizedAttributes.php`. Laravel 11 requires this.
   - Check that the relation overrides in `TraitCustomModelSchema` still match the parent signatures (PHP fatals on
     boot if not).
   - **Known existing quirk, do not change here:** `mutateAttribute()` discards `parent::mutateAttribute()`'s result.
     Changing it would change the index output. Report it to the user as a separate issue.

8. **Zero deprecations**:
   - `cache:clear`; the container deprecations log must be empty for `App\` code.
   - Load every page and endpoint from the snapshot list in dev. The profiler's "Deprecations" tab / `var/log/dev.log`
     (`php.INFO: Deprecated`) must not mention `App\` or our config.
   - Run `bin/console lint:container`, `lint:twig templates`, `lint:yaml config`, `lint:xliff translations`.
   - Remaining vendor deprecations (illuminate 9, elastica) are noted in the PR, not fixed.

9. **Docs**: in `AGENTS.md`, update the stack table (Symfony 6.4, PHP 8.3, Eloquent 9), "Routes are attribute-based
   (`#[Route]`)", and remove the `webpack_encore.yaml` gotcha.

10. **Verify against the baseline** (see Verification), rebuild the prod image, then open the PR.

## Phase 2: Eloquent 10 — branch `chore/eloquent-10` (from `chore/symfony-6.4` until that is merged), one PR

   `config/packages/eloquent.yaml` if any key changed. The current file uses
   `driver/host/port/database/username/password` and `eloquent: null`.
3. Laravel 10 breaking changes to check in `src/`:

     and `src/Model`

     compatible (wider parameter); check the subclasses in `src/Resource/ElasticSearch/`
   - `Relation::getBaseQuery()` return type
   - Monolog 3 (already done in phase 1)
4. Optional Rector help: dry-run `driftingly/rector-laravel` with `LaravelSetList::LARAVEL_90` and `LARAVEL_100`,
   applied as a temporary dev dependency. Only apply hits that concern Eloquent or Collections, then remove the package.
5. Zero deprecations from our code, as in phase 1 step 8.
6. Update `AGENTS.md` (Eloquent 10). Verify against the baseline and open the PR.

## Verification (after each phase)

- `docker compose up --build`: the container starts, `composer install` and `cache:clear` succeed, and the startup
  script creates the indexes.
- `app/scripts/upgrade-snapshot.sh var/snapshots/after-phaseN`, then `diff -r var/snapshots/before
  var/snapshots/after-phaseN`:
  - **routes and ES documents must be identical**
  - HTTP responses must be identical, except volatile fields (timings, the debug toolbar)
- Full reindex of both indexes (`app/scripts/reindex.sh`) completes without errors.
- Manual browser check (chrome-devtools MCP) of charter search, charter detail with prev/next, tradition search and
  tradition detail in EN and FR. No console errors; the profiler shows no `App\` deprecations.
- `docker build --target prod .` succeeds (`composer install --no-dev --classmap-authoritative`). Then boot the prod
  image with `APP_ENV=prod` and check `/health` plus one charter page.
- `pnpm build` is unaffected (no frontend changes), but run it once to confirm the Vite bundle integration
  (`pentatrion/vite-bundle` 7.1 on SF 6.4).

## Out of scope
